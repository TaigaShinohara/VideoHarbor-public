# 初回ガイド（オンボーディング）— 設計と検証の記録

実装：`extension/onboarding.js`、`extension/onboarding.css`、画面本体は `extension/workspace.html` 内の `#onboarding`。設計は mobile_onboarding スキル 0.5.0 に従い、ブラウザ拡張（Chrome / iOS Safari の Web ページ）に適応した。適応点は末尾に明記する。

## コンセプトの読み取り（正本 DESIGN.md から）

- コンセプト：ページを見ている人が、保存できるものを確認し、必要なアイテムや場面を意図的に残し、正直な結果と回復路を得る。
- 解決する困りごと：保存のしかたが分からない／どれが目的の動画か見分けられない／保存できたか不安。
- 最初の小さな成功：開いてすぐ候補が並び、目的の1件を保存して実ファイルを確認できること。
- 守るべき契約（不変）：完全ローカル・外部通信ゼロ、最小権限、明示開始、未保存保護、保存完了を偽らない。ガイドは計測・外部送信を一切行わず、回答は端末内の localStorage にだけ保存する。

## 4つの達成条件（今回の具体化）

- 何のためのアプリか：ユーザーが「ページの動画を端末に残す道具」と言い直せること。
- スリーステップ：①動画のページで開く ②候補から選ぶ ③残して、確かめる。
- ワクワクする瞬間：フック（持ち帰れる宣言）と、試し操作の結果ページ、最後の期待ページに配置。
- 早く使いたい：最後の「動画を探す」はガイドを閉じてそのまま実タブの再スキャンを開始し、最初の成功へ直結させる。

## 回答の使い道

- マッチ宣言の文面とアイコンが、選んだ悩みに対応して変わる。
- 価値ページ（5〜7）の並びが、選んだ悩みに最も効く価値から始まるよう入れ替わる。
- 回答は localStorage（`videoharbor.onboarding.v1`）に端末内だけ保存し、完了状態と版番号と一緒に持つ。外部送信・計測はしない。

## 適応点（モバイルアプリ前提のスキルからの変更）

- 触覚は OS 標準 API が Web に無いため、`navigator.vibrate` の短い単発（小8ms／中24ms／大40ms）で代替した。端末設定で無効な環境では鳴らない。iOS Safari は Vibration API 非対応のため、その環境では見た目の反応と言葉だけが返る。
- ページ送りはプラットフォーム標準の PagerView 等ではなく、CSS transform のトラック＋スワイプ／ボタン／矢印キーで実装した（拡張機能はビルドなし・外部依存なしの制約のため）。
- 自動表示の抑制：自動テスト環境（`navigator.webdriver`）では初回表示をしない。手動確認用に `?guide=1` で強制表示、`?guide=off` で抑制できる。再表示はヘルプ内の「使い方ガイドを見る」からいつでも可能。
- スキップした場合は、その版では自動表示を繰り返さない（完了とは区別して `skipped` として保存）。
