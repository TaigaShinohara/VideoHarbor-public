# AGENT_OPERATIONS — VideoHarbor の監査と操作カタログ

AI エージェントが VideoHarbor を機械から使うための正本。監査（現状把握）、到達レベル、操作カタログ（棚卸し）、人間専用操作の宣言を 1 枚に持つ。コマンドの使い方は `docs/AGENT_GUIDE.md`、機械可読な目録は `docs/agent-manifest.json`。

- 監査日: 2026-11-24
- 対象版数: 0.6.4（監査時点）→ 本作業で 0.6.5
- スキーマ版数: 1

## 1. 監査（チェックリスト様式）

### 現状把握

| 項目 | 判定 | 根拠 |
|---|---|---|
| データの保存場所と形式が特定できている | 済 | 候補・ジョブ状態は拡張ページのメモリ内のみ（永続 DB なし）。永続化は初回ガイドの状態だけ（workspace ページの localStorage キー `videoharbor.onboarding.v1`）。保存済みファイルは OS のダウンロードフォルダ配下 `VideoHarbor/<日付>/`。サーバー・外部送信なし |
| 業務ロジックが UI から分離されている | 済 | 判定・命名・形式ポリシーは純粋モジュール（`extension/utils.js`、`output-format.js`、`filenames.js`、`discovery.js` ほか）に分離され、Node テストが直接 import する。例外: `collector.js` と `page-video-recording.js` は注入関数の制約で YouTube ホスト判定を重複保持する（`utils.js` のコメントで三者の一致を義務付け） |
| 外部から触れる経路の有無 | 未（本作業で追加） | CLI・API・ディープリンクなし。開発用の npm スクリプト（check / test / package）はアプリの機械経路ではなかった |
| ID の安定性 | 一部 | 候補の事実上のキーは完全 URL（`mergeItems` が完全 URL で重複解消）。ただし候補はセッション限りで永続 ID はない。出力ファイル名は日時＋連番で一意だが識別子ではない |
| 実行履歴と失敗理由が残っているか | 未（本作業で一部追加） | 保存済みファイル一覧と失敗理由は画面内（セッション内）だけ。永続の実行履歴はなかった。本作業で CLI 自身の実行履歴（`.agent-state/history.jsonl`）を追加。拡張本体の保存・録画の履歴は引き続き画面内のみ |
| テスト基盤とスクリーンショット取得経路 | 済 | `node --test` 単体テスト群、`scripts/check.mjs`、Playwright のブラウザスモーク群。画面要素は安定した `id` を持ち、本作業で主要操作に `data-testid` を追加 |
| 現在の到達レベル | **L0**（本作業前） | 状態も結果も画面でしか分からず、機械可読な経路がなかった |

### 到達レベルと目標

- 本作業前: **L0**（GUI のみ）
- 目標: **L2（範囲付き）** — 読み取り（status / list / get / history / doctor）、保存の計画（plan-save、ドライラン相当）、検証（verify）を機械化する。保存・録画の「実行」は Chrome 拡張の仕様上、利用者の操作とブラウザ文脈（tabCapture、getDisplayMedia、OS の保存ダイアログ、任意ホスト権限の許可ダイアログ）が必須であり、機械経路を作れないため人間専用として宣言する（第 3 節）。計画と実行で同じ芯（純粋モジュール）を通るため、計画の結果は実行の結果と一致する。
- MCP: なし（L2 の操作と検証が動いた段階。日常的に AI が自律運用するアプリではないため、今回は入れない。将来入れる場合は CLI のスキーマを正本として生成する）
- SDK: 作らない（需要なし。JSON スキーマとガイドで足りる）

## 2. 操作カタログ

粒度は「利用者が画面で名前を言える操作」。機械の経路は CLI（`node scripts/agent-cli.mjs <command>`、npm では `npm run agent -- <command>`）。

| 操作名 | 対象 | 人間の手順 | 機械の経路 | 入力 | 出力 | 副作用 | 破壊的 | 人間専用か |
|---|---|---|---|---|---|---|---|---|
| scan-candidates | 開いているタブのページ | 拡張を開く／「再スキャン」を押す | なし（B: 画面まで案内） | ページ URL | 候補一覧（画面） | ページへのスクリプト注入（activeTab の範囲） | いいえ | 実行は人間。候補の判定規則は芯モジュールが持ち、plan-save が同じ規則で事前判定できる |
| plan-save | 保存候補 1 件 | 候補を見て形式を選ぶ前の判断 | CLI `plan-save` | 動画 URL、ページ URL、種別、MIME、形式 | 対応可否、形式の選択肢、出力ファイル名、理由 | なし（読み取りのみ。履歴への記録は `--dry-run` で抑止可） | いいえ | いいえ（機械化済み） |
| save-video | 保存候補 1 件 | 候補の保存ボタンを押し、形式を選び、OS の保存先ダイアログで確定 | なし（C） | 候補、形式 | ファイル、または失敗理由 | ダウンロードフォルダへファイル作成 | いいえ | 人間専用。理由: downloads API と OS の保存ダイアログ、ページ文脈での組み立てが利用者操作を必須とする |
| save-retained-media | 準備済みの動画 | 「準備済みの動画を保存・共有」を押す | なし（C） | 保持中のデータ | ファイル／共有シート | ファイル作成、モバイルでは共有シート表示 | いいえ | 人間専用。理由: 保存ダイアログと Web Share は利用者操作が必須 |
| discard-retained-media | 準備済みの動画 | 「準備済みの動画を破棄」を押す | なし（C） | 保持中のデータ | 破棄完了 | 保持データの削除（取り消し不可） | **はい** | 人間専用。理由: 取り消せない破棄であり、保持データはブラウザ文脈にしか存在しない |
| record-video | 動画要素 1 つ | 録画タブで対象を選び開始し、止める | なし（C） | 対象の動画 | WebM ファイル | タブのメディア捕捉 | いいえ | 人間専用。理由: tabCapture と録画の開始・停止は利用者操作とブラウザ文脈が必須 |
| record-tab | タブ全体 | 録画タブで開始し、止める | なし（C） | タブ | WebM ファイル（最大 30 分） | タブの捕捉 | いいえ | 人間専用。同上 |
| record-screen | 画面／ウィンドウ | OS の選択画面で対象を選んで開始し、止める | なし（C） | OS が提示する画面／ウィンドウ | WebM ファイル | 画面の捕捉 | いいえ | 人間専用。理由: getDisplayMedia の選択画面は OS／ブラウザのダイアログであり自動化しない |
| cancel-save | 実行中の保存 | 「保存を停止」を押す | なし（B） | 実行中ジョブ | 停止結果、中断分の保持 | ジョブ状態の変更 | いいえ | 実行は人間。CLI の対象外（ブラウザ文脈のジョブのみ存在） |
| retry-interrupted | 中断した保存 | 「中断分を再試行」を押す | なし（B） | 中断ジョブ | 再試行結果 | ダウンロードの再開 | いいえ | 同上 |
| grant-frame-access | 埋め込み元サイト | 候補の「アクセスを許可」を押し、Chrome の許可ダイアログで承認 | なし（C） | サイトのオリジン | 任意ホスト権限の付与 | 拡張の権限状態の変更 | いいえ | 人間専用。理由: 任意ホスト権限の付与は Chrome の権限ダイアログが必須（AGENTS.md のハウスルールでも無断追加を禁止） |
| open-onboarding | 初回ガイド | 「はじめてガイド」を押す | なし（B） | なし | ガイド画面 | なし | いいえ | 実行は人間。状態キーは status が開示する |

## 3. 人間専用と宣言する操作（理由付き）

| 操作 | 理由 |
|---|---|
| save-video / save-retained-media の実行 | Chrome の downloads と OS の保存先ダイアログ、モバイルの Web Share は利用者の操作を必須とする。機械が行うのは同じ芯による事前計画（plan-save）まで |
| record-video / record-tab / record-screen の実行 | tabCapture と getDisplayMedia は利用者の操作とブラウザ文脈が必須で、画面／ウィンドウの選択は OS のダイアログである |
| grant-frame-access | 任意ホスト権限の付与は Chrome の権限ダイアログが必須。検出と不足の提示は doctor と画面が行う |
| discard-retained-media | 取り消せない破棄であり、対象データはブラウザ文脈にしか存在しない |
| Chrome Web Store への提出・支払い | 本作業の範囲外（提出は本人の明示指示でのみ行う既存ルールを維持） |
| 映像・音の質感の判定 | 身体感覚の判定は自動テストで確認済みにしない（AGENTS.md のハウスルール） |

## 4. CLI 契約の要点（詳細は AGENT_GUIDE.md）

- 成功・失敗とも JSON の包みを統一し、`meta.schema_version` は 1。
- 終了コード: 0 成功 / 1 入力誤り / 2 アプリ側失敗 / 3 ポリシー拒否（未対応サイト等） / 4 対象なし。
- 共通フラグ: `--json`（既定）/ `--human` / `--dry-run` / `--yes` / `--idempotency-key <key>` / `--timeout <sec>`。
- 冪等性: plan-save は同じ `--idempotency-key` の再実行で最初の結果を返す（二重に計画を作らない）。
- 秘密情報: 出力に値を含めない。status は権限「名」と状態の有無だけを返す。
- 履歴: CLI の実行は `.agent-state/history.jsonl`（git 管理外）に追記される。`--dry-run` では記録しない。
